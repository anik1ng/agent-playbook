# nsarchive × agent-playbook × cmux — архитектура конвейера, v2

Пересборка документа от 2026-08-07 после жёсткого ревью, четырёх серий экспериментов
(песочница agy, hooks, cmux) и консультации Fable-практика, работающего по playbook внутри
nsarchive. Версия v1 проектировала вокруг agterm и держалась на тезисе, который
эксперименты опровергли; эта версия не содержит ни одного утверждения «принято на слово» —
всё в §4 либо проверено исполнением, либо явно помечено как хвост.

Рабочий конспект решений — `2026-08-10-cmux-agy-pipeline-plan.md` (тот же каталог).

---

## 1. Исходное положение

**Есть:** agent-playbook (человек мержит PR не читая диффы; CI проверяет форму,
кросс-семейный ревьюер проверяет истину исполнением; тесты неприкосновенны). Три скилла
`/do`, `/ship`, `/review` в `.agents/`. Проект nsarchive живёт по нему с 2026-05.

**Подписки:** Claude, Gemini. Кросс-семейный ревьюер — agy (Antigravity), единственная
доступная не-авторская семья. Codex недоступен (бинарь в PATH есть, подписки нет).

**Терминал-оркестратор:** cmux (заменил agterm из v1) — нативный macOS-терминал под
агентов: группы/воркспейсы/пейны/surface, скриптуемый CLI и unix-socket, встроенный
браузер, уведомления, iOS-компаньон.

**Болит (без изменений с v1):** запуск работы руками; невидимость застрявших агентов;
ревью через `nohup` с логом в `.git/` — невидимо и привело к инциденту (ревьюер с
`--dangerously-skip-permissions` искал файл скилла по всему диску).

## 2. Целевая архитектура

Карта cmux: **группа = проект, воркспейс = worktree** (1 workspace = 1 worktree =
1 ветка = 1 PR — дословно branch discipline из AGENTS.md).

```
group "nsarchive"
├── workspace «думалка»      Fable 5      главный чекаут, без worktree
│     единственное место, где человек РАЗГОВАРИВАЕТ. Интервью, пробы,
│     решения. Выход: seed-issues и бриф (комментом в issue).
│
├── workspace «spec #N»      Sonnet/Opus  свой worktree
│     пишет спеку и план ИЗ ГОТОВОГО БРИФА, заводит суб-issues, шипит PR.
│     Не интервьюирует. Упёрся → blocked: бриф неполон.
│
├── workspace «do #N»        дешёвый тир  свой worktree   × N параллельно
│     реализация по плану, PR. Параллель в разных областях не ограничена.
│
└── workspace «review #N»    agy          worktree ревьюера, detached HEAD,
      --sandbox + hooks-политика. Запускается на PR и на каждый fix-push.
      Вердикт → коммент на PR → cmux notify.
```

### Принципы (исправленные после экспериментов)

**Видимость и безопасность — РАЗНЫЕ свойства.** v1 утверждала, что живая сессия — условие
работоспособности песочницы («headless без обхода не делает ничего»). Это оказалось
ошибкой конфигурации, а не свойством agy (§4.2). Правда такова:

- **Видимость** даёт cmux-сессия: живой вывод, уведомления, ответы на запросы.
- **Безопасность** дают `--sandbox` + hooks-политика — и они работают в любом режиме.
- Интерактивная сессия — **осознанный выбор человека** (каждый выход из песочницы —
  видимое решение), а не техническая необходимость.

**Автоматическим может быть запуск. Автоматической выдачи прав быть не должно** —
правило из v1 устояло и теперь имеет машинную форму: PreToolUse-хук с deny.

**Конвейер живёт внутри cmux.** Управлять cmux могут только процессы, запущенные внутри
него (проверено: снаружи «Access denied»). Ship-сессия и думалка и так внутри — ок; но
внешние крон/скрипты воркспейсы создавать не смогут.

## 3. Решения

### 3.1 Worktree на каждую задачу и каждое ревью

Без изменений с v1 по сути, с тремя уточнениями:

- **Worktree ревьюера стоит на detached HEAD** (sha head'а PR): git не позволяет одной
  ветке быть выписанной в двух worktree, а ветку держит worktree автора. Побочный плюс:
  предусловие протокола «HEAD == head PR» выполняется конструктивно.
- **Worktree ревьюера персистентен на PR**: суперсессия закрывает *сессию*, дерево живёт
  до закрытия PR (fix-push = `git fetch` + `reset --hard <new-head>`, install
  инкрементален). Это снимает большую часть цены «ревью на каждый push».
- Аргумент за изоляцию ревьюера сильнее, чем думала v1: протокол требует мутаций кода,
  но не требует их отката (дефект, чинится в playbook — §5), и ревьюер уже трижды умирал
  посреди работы в дереве автора — с риском оставить автору молча изуродованный код.

Провижининг — обкатанные скрипты из mewmusic (`setup-worktree.mjs` и родня), с одной
правкой: worktree ревьюера получает **отфильтрованный** `.env.local` — только переменные
гейта. API-ключи проекта ревьюеру не нужны ни в одном сценарии.

### 3.2 Думалка / станок и лестница спеки

Разделение подтверждено историей проекта: думалка-сессия уже существует де-факто
(d04223af породила issues #93–96), а единственный дизайн-баг уровня механизма (PR #98)
прошёл именно там, где спека была написана *после* кода.

Лестница: **обсуждение (Fable) → бриф → спека+план (средний тир) → суб-issues**.
Это расширение brief-механизма AGENTS.md (не реверс правила «one session»): штатным
становится путь, который playbook уже описал для «brainstorm that outgrows its session».
Брейншторм-fallback в `/do` остаётся для средних задач — порог у человека.

**Бриф — комментом в seed-issue**, не файлом и не промптом:

- worktree не разделяют незакоммиченные файлы — файл из думалки физически не доедет до
  spec-worktree; GitHub уже является общей шиной, `/do` и так читает комменты
  («comments are part of the spec»);
- **правило старшинства обязательно**: бриф-коммент помечен `SUPERSEDING`, тело issue
  ссылается на него. Наблюдаемый режим отказа nsarchive — не отсутствие записей, а их
  расхождение (переписанное тело #95, патч-баннеры в плане реархитектуры); четвёртый
  артефакт без владельца актуальности умножил бы рассинхрон;
- файл в `docs/superpowers/brainstorm-briefs/` коммитит spec-сессия в составе spec-PR —
  требование playbook о committed-артефакте выполняется, но позже.

**Эпистемика брифа обязательна.** Корень бага PR #98 (запись логина до второго фактора):
думалка *сомневалась* — «the session might not be created until after OTP» — но сомнение
не пережило конвертацию в issue; хеджи выравниваются до утверждений, и цепочка
/do → PR → Flash-аппрув несла ложный факт как данность. Поэтому каждый факт брифа несёт
метку: **[проверено исполнением] / [прочитано в исходниках] / [предположение]** — и
думалка обязана исполнять пробы во время интервью: средний тир, пишущий спеку из брифа,
проб не сделает.

**Компенсация вместо «человек читает спеку».** v1 предлагала человеческое чтение спеки —
это противоречит зафиксированному решению владельца (no-spec-plan-review-gate: ревью
мокапами и живым приложением). Вместо мёртвого правила: спек-ревью agy обязано
**прогнать пробы** по каждому [проверено]-факту, а неразмеченное утверждение о поведении
платформы — блокер спеки. Спека и так едет PR-ом и получает кросс-семейное ревью.

### 3.3 Роутинг моделей

| Роль | Тир | Обоснование |
|---|---|---|
| Решать + пробы (думалка) | Fable 5 | дорого стоит решение и проверка посылок |
| Спека+план из брифа | Sonnet/Opus | структурирование уже принятых и проверенных решений |
| Реализация | дешёвый | качество гарантируют CI и ревью |
| Ревью (кода и спек) | agy | единственная не-авторская семья; кросс-семейность — the one hard rule |

### 3.4 Ревьюер: модель песочницы agy (проверено экспериментами, §4.1)

Точная модель, заменяющая ошибочную из v1:

- **Команды в песочнице бегут молча**, без промптов. Сеть дочерним процессам отрублена;
  файлы workspace — RW; системные пути (`/etc/passwd`, часть `~/.config`) — читаются;
  чувствительные (`~/.zshrc`, `~/.ssh`) — hard deny; файлы вне workspace — промпт
  «outside workspace» с причиной.
- **Bypass-одобрение = команда выполняется ВНЕ песочницы целиком** («full network and
  disk access»). Одобрение — поштучное и видимое; правило «always allow … (persist)»
  создаёт постоянный тихий обход (`unsandboxed(<prefix>)` в settings.json) — в
  ревью-сессиях разрешено только «на эту сессию», persist — только узким префиксом
  (`unsandboxed(gh pr comment)` допустим, `unsandboxed(gh)` — дыра, покрывает merge).
- **`.agents/hooks.json` + PreToolUse guard — машинная политика** (работает, проверено:
  «Tool call denied by pre-tool hook»):
  - `deny` для `git push`, `gh pr merge`, `gh pr close` — впервые у agy есть настоящий
    deny list; report-only перестаёт держаться «only by this sentence»;
  - `ask` + вызов `cmux notify` перед ним — уведомление «ревьюер ждёт тебя» (бейджи
    cmux для agy не работают никогда: список интеграций захардкожен);
  - хуки бегут вне песочницы с полными правами; cwd хука = каталог `hooks.json`.
- `ask_permission` / permissioned-github в локальном CLI **отсутствует** (managed-only) —
  скоупные gh-гранты вычеркнуты.

Итоговый профиль ревьюера: автономен внутри песочницы (пробы, мутации, тесты — ноль
вопросов), необратимое запрещено машиной, наружу (сеть: `gh`, БД) — только через видимое
решение человека или узкий персист. Секреты *текущего* проекта ревьюеру видны в объёме
отфильтрованного env — это остаточный риск, принятый осознанно (§6).

### 3.5 Запуск, суперсессия, петля уведомлений

**Ship вызывает `.agents/auto-review.sh <pr>` — и всё.** Способ запуска (nohup или
cmux-воркспейс) — решение самого скрипта: его рендер — локальная часть репозитория.
Это чинит дефект v1: `nohup` был зашит в вендор-нейтральный ship-скилл, и сессионная
модель требовала бы править Class-A шаблон. (Правка шаблонов — §5, п.3.)

На этой машине рендер скрипта делает:

1. worktree ревьюера (создать при первом ревью PR / `fetch` + `reset` при fix-push),
   detached HEAD на head sha;
2. **суперсессия**: `cmux close-workspace "review #N"` если жив (проверено: закрытие
   воркспейса убивает дерево процессов — зомби-ревьюеров не будет);
3. `cmux workspace create --name "review #N" --cwd <worktree>` с surface
   `agy --sandbox -i "/review N"`.

**Петля уведомлений:** guard-хук зовёт `cmux notify` перед каждым `ask`; финальный шаг
протокола ревью — notify о вердикте. Коммит-статус `auto-review` из nohup-модели на этой
машине не нужен: «ревью идёт/умерло» видно в воркспейсе, вердикт — как и всегда — только
коммент (`Reviewed-by:, head <sha>`). **Актуален только вердикт, чей head-sha равен
текущему head PR**; устаревшие вердикты помечаются/сворачиваются.

### 3.6 Уборка

Порядок жёсткий (сессия сидит внутри того, что удаляет), с двумя страховками сверх v1:

1. `gh pr view --json state,mergedAt` → **merged? иначе стоп**;
2. **всё запушено?** `git log origin/<branch>..<branch>` пуст — иначе стоп: коммиты,
   которых нет на GitHub, `-D` потеряет безвозвратно (запушенные хранит `refs/pull`
   даже после auto-delete ветки);
3. teardown тестовых ресурсов (`worktree:teardown` изнутри worktree);
4. `cd` в главный чекаут;
5. `git worktree remove` — **без `--force`, всегда**: его отказ на грязном дереве и есть
   настоящая защита от потери работы; отказ = стоп, не эскалация;
6. `git branch -D`;
7. `cmux close-workspace` — последним: он убивает шелл со скриптом.

Подметание на старте `/do` (упавшие сессии, брошенные worktree, осиротевшие тестовые БД
через `--sweep`) — важнее команды: забыть невозможно.

### 3.7 БД-модель nsarchive и схемный замок

Из консультации практика — v1 здесь была hand-wave:

- **Архив** (402 таблицы, ~8M строк, грузится только Go-пайплайном) — ОБЩИЙ, read-only,
  на worktree НЕ клонируется: параллельное чтение безопасно, а reload архива на каждый
  worktree — неподъёмно.
- **Настоящая опасность — app-схема и migration-head**: две ветки с миграциями от одной
  базы обе получат `0004_*` и сломают друг друга. Правило «одна in-flight ветка на
  `db/*.sql`» становится **машинным**: проверка на СТАРТЕ в `/do` (задача трогает схему +
  открытая ветка с миграциями уже есть → стоп и вопрос человеку ДО работы), в ship —
  подстраховка. Отказ по умолчанию + человеческий override. Схемы не трогает ~90% задач —
  их это не касается.
- Причина машинности: magnet-привычка проверять открытые PR сегодня выполняется
  формально (открытых PR почти всегда ≤1) и умрёт ровно к моменту, когда worktree сделают
  её нужной.

### 3.8 Очередь приёмки (вместо лимита на worktree)

Параллельные worktree в разных областях **не ограничиваются** — поиск + документы +
админка одновременно это норма и цель схемы. Ограничение одно, и оно индикатор, не запрет:
**≥3 готовых PR ждут мержа человека → сначала разгрести, потом стартовать новые.**
Висящие PR протухают (база уезжает из-под них) и конфликтуют; приёмка (merge, ручной
тест на общем :3000) — серийная по природе. Жёсткими остаются только физические границы:
схемный замок и magnet-файлы.

### 3.9 Где живёт интеграция

Личный слой машины: рендер `auto-review.sh`, hooks.json ревьюера, guard.sh,
launcher-функции (`worktree + провижининг + workspace` — три шага, не два),
`~/.gemini/…/settings.json`. В `templates/` playbook не попадает ничего cmux-специфичного;
точка стыковки — сам скрипт `auto-review.sh`, чей рендер и так объявлен локальной частью.
Дефекты playbook, не зависящие от терминала, — отдельным PR (§5).

## 4. Доказательная база

### 4.1 Проверено экспериментом (сессии 2026-08-07…10)

**Песочница agy, интерактив (`--sandbox`):**

| Проверка | Результат |
|---|---|
| `gh api user`, `psql` | работают только через bypass-промпт; одобрение = исполнение ВНЕ песочницы |
| `~/agy-canary.txt` (вне workspace) | промпт «outside workspace», после «Yes» — прочитан |
| `~/.zshrc`, `~/.ssh/config` | hard deny, Operation not permitted |
| `/etc/passwd`, `~/.config/starship.toml` | читаются молча (системный RO-слой) |
| команды в песочнице (`echo`, `git push` без remote) | бегут молча, без промптов; сеть детям отрублена |

**Правила разрешений:** «persist» из bypass-диалога записывает `unsandboxed(<prefix>)` в
`~/.gemini/antigravity-cli/settings.json` (наблюдалось: `unsandboxed(gh)`; удалено как
дыра — префикс покрывал `gh pr merge`). Грамматика из бинарника:
`command() / unsandboxed() / read_file() / write_file() / read_url() / mcp() / execute_url()`.

**Hooks:** `.agents/hooks.json`, PreToolUse, guard-скрипт → `git push` жёстко отклонён
(«Tool call denied by pre-tool hook: review policy: reviewer is report-only») без вопроса
человеку. Провал первой попытки — наша ошибка пути (cwd хука = каталог hooks.json).
Документация механизма реальна: `builtin/skills/agy-customizations/docs/hooks.md`
(события PreToolUse/PostToolUse/PreInvocation/PostInvocation/Stop; decision
allow/deny/ask/force_ask; permissionOverrides; хуки — с полными правами).

**`ask_permission` (permissioned-github):** в локальном CLI тула НЕТ — managed-only.

**cmux:** управление только изнутри cmux («Access denied — only processes started inside
cmux can connect»); `workspace create --layout` с командой работает; закрытие воркспейса
убивает дерево процессов (sleep-тест: жив при открытом, мёртв после закрытия). Бейджи
«awaiting input» — только для захардкоженных интеграций (Claude/Codex/OpenCode/Grok/Pi/
Kiro), agy туда не входит; универсальный канал — `cmux notify` из самого процесса.

**Транскрипты agy:** `brain/<id>/.system_generated/logs/transcript.jsonl` существует,
структурный JSONL; статусов ожидания в нём нет (только DONE/RUNNING) — вотчер по
транскрипту вычеркнут, уведомления — через guard-хук.

**Из консультации практика (по репо и 66 транскриптам nsarchive):** думалка-практика уже
существует (d04223af → #93–96); баг PR #98 — потерянный при конвертации хедж, не слабость
модели; медиана fix-push на PR — 0–1 (ре-ревью на каждый push почти бесплатно);
единственный улетевший в прод баг (#68) — живой DOM, класс, который изоляция не ловит.

### 4.2 Отозвано (v1) — для калибровки

1. «Headless без обхода не делает ничего; дефект в headless как таковом» — ошибка
   конфигурации (правило клали не в тот файл), у agy есть и allowlist, и hooks.
2. «Сессия agterm — условие работоспособности песочницы; видимость = безопасность» —
   следствие п.1; свойства разделены (§2).
3. «`--sandbox` держит, бланкетный флаг снимает» — верно, но неполно: и каждое одобрение
   bypass снимает песочницу для той команды; правда — в §3.4.
4. «Своя тестовая БД на каждый worktree» — для nsarchive неверно (архив); правда — §3.7.
5. «Правило allow хранится в скрытом кэше, не в settings.json» (со слов agy) — ложь
   модели о себе: найдено в settings.json. Подтверждена и калибровка v1: agy о себе
   ошибается, пометки [док] у него не гарантируют документированности.

### 4.3 Хвосты — проверить при внедрении

1. `cmux notify` из-под sandbox-agy изнутри cmux-воркспейса (тест шёл вне cmux).

## 5. Изменения в playbook (PR, не зависящий от терминала)

1. **Область ревьюера не ограничена** — корень инцидента. ADOPT.md требует прав «wide
   enough … a soft-denied tool hollows the review out», и ни слова про границу ЧТЕНИЯ:
   «широко» должно означать инструменты, а не радиус. Чинится в ADOPT.md («Reviewer
   CLI»), шапке `auto-review.sh`, AGENTS.md «Reviewer protocol».
2. **Мутации не откатываются** — протокол требует удалять пробы, но не требует
   откатывать мутации; ревьюер, умерший посреди мутации в чужом дереве, оставляет автору
   молча сломанный код. Чинится в review/SKILL.md.
3. **Способ запуска ревью зашит в ship-скилл** (`nohup … &`) — переносится внутрь
   `auto-review.sh` (self-detach), ship просто вызывает скрипт. Задевает ship/SKILL.md,
   auto-review.sh, settings.json (allow-правило без nohup), ADOPT.md §3.

Отдельно, уже в AGENTS.md самого nsarchive (не в шаблоны): схемный замок §3.7, правило
старшинства брифа §3.2, эпистемические метки, очередь приёмки §3.8.

## 6. Слабые места (честный остаток)

1. **Секреты текущего проекта видны ревьюеру** — гейту нужна БД; фильтрация env сужает,
   но не закрывает. Принято осознанно.
2. **Каждое bypass-одобрение — полный выход команды из песочницы.** Мицигируется
   видимостью и узкими персистами, но человек, устало жмущий «allow», — реальный вектор.
3. **Песочница agy — частично денайлист** (системный RO-слой читается). Свой внешний
   `sandbox-exec`-профиль остаётся опцией усиления, в план не включён.
4. **Класс живого DOM не закрыт** (§7): изоляция чинит документированные зазоры
   протокола, но не баг, который реально уехал в прод.
5. **Bus factor** мягче, чем в v1 (cmux — живой продукт, вся политика — файлы в личном
   слое), но конвейер по-прежнему один-человеческий и macOS-only.
6. **Дисциплина думалки** держится на правиле «решение, оставшееся в транскрипте, не
   принято» — форсировать его машиной пока нечем.

## 7. Phase 2 — браузерный слой ревью

Не в этой итерации, но зафиксировано: единственный улетевший в прод баг nsarchive (#68,
React переиспользует `<input>` между шагами формы) невидим и юнитам
(renderToStaticMarkup), и ревьюеру без браузера. Кандидат: ephemeral dev-сервер в
worktree ревьюера (свой порт) + Playwright или встроенный браузер cmux (скриптуемый).
Потребует явного исключения из «агенты не запускают dev-серверы» — правило защищало
общий :3000 человека, к собственному worktree ревьюера по духу не относится.

## 8. Что специально НЕ делается

- **Мерж не автоматизируется.** Человек мержит; на этом стоит вся конструкция.
- **`templates/` не получают ничего cmux-специфичного** — только дефекты §5.
- **Контейнер для ревьюера** — не нужен на текущем профиле риска: песочница + hooks
  закрывают документированные зазоры; вернётся в повестку, если п.3 из §6 станет болеть.
- **Boundary Rules прозой** как средство изоляции — отвергнуты, как и в v1: «a rule an
  agent must remember is a rule that gets skipped» — теперь это подтверждено и хуками.
